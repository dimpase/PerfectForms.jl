This project uses polyhedral_common by Mathieu Dutour Sikiric as an external,
pinned build dependency. No upstream source archive or backend executable is
distributed in this repository or its data archives. CMake FetchContent
fetches the upstream repository and submodules into the build directory;
backend/pins.json records their exact revisions.

Repository: https://github.com/MathieuDutSik/polyhedral_common
The pinned commit and recursive submodule revisions are recorded in pins.json.
The upstream GPL version 2 text is retained as UPSTREAM_COPYING for reference.
Upstream copyright notices remain in the external source checkout. The local
C++ exporter compiles upstream headers when built; making those sources an
external dependency does not settle the backend's license-version or linked
dependency compatibility questions. No relicensing of upstream code is claimed.

Its permutalib dependency is pinned in pins.json; its supplied LGPL text is
retained as PERMUTALIB_COPYING.LGPL for reference. The other pinned source
dependencies and their notices remain in the external upstream checkout.
The backend also requires an installed nauty/Traces library and headers.
Its library path and version are recorded in local build provenance.

export_perfect.cpp is the local exporter, not an upstream supported interface.
CMakeLists.txt and cmake/ build this exporter from unmodified upstream headers.
No upstream code patches have been submitted. Historical audit issue reports
are preserved in ArithmeticVoronoi:
https://github.com/dimpase/arithmetic_voronoi/tree/main/upstream_reports
The Julia adapter invokes this separate executable through typed exact JSON.
No code was copied from SLnCohomology, HAP, or the Magma implementation.
UPSTREAM_STATUS.txt records the review of fixes for those three issues and
explains which parts of this interface remain necessary.

This package was extracted from ArithmeticVoronoi commit
8f237bb9d311ee64f89b52d24da65ffe290cc5de; our code keeps its existing license
in ../LICENSE. ArithmeticVoronoi's sealed dataset retains the earlier exporter
and build recipe as historical provenance, without upstream sources or a
compiled backend. Its BACKEND_AUDIT.md records that historical layout.
