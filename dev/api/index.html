API reference

Enumeration and requests

PerfectForms.enumerate_perfect_forms — Function

Enumerate perfect forms from an upstream namelist or quadratic discriminant.

enumerate_perfect_forms(input_text; config, ...) passes a namelist unchanged to the exporter. enumerate_perfect_forms(D; dimension=2, config, ...) uses the quadratic-order convenience constructor; D=1 selects classical forms. With no positional argument, pass upstream options as tspace and data.

Return (data, raw, run_directory, process_info) after checking the process and export protocol. Exact numeric values remain JSON strings. Mathematical validation is the caller's responsibility. Remaining keywords control run_exporter, including its deadline and memory budget.

source
PerfectForms.perfect_form_request — Function

Build a perfect-form enumeration request from upstream T-space options.

tspace and data accept a named tuple or dictionary using upstream option names. T-space types, dimensions, field polynomials and file inputs are passed to upstream without a package-specific whitelist. Use absolute paths for auxiliary files: the child runs in a private request directory.

The default selects classical binary forms and GMP arithmetic. The compiled exporter implements perfect-form/facet enumeration, not lower complexes.

source

Build a request for a quadratic order of discriminant D, in any rank.

Use D=1 for classical rational forms. Positive and negative nonsquare discriminants congruent to 0 or 1 modulo 4 select real and imaginary quadratic orders, respectively. Fundamental discriminants select maximal orders; a nonfundamental discriminant describes the corresponding nonmaximal order. dimension defaults to two. No list of tested fields limits accepted inputs. Use the keyword-only method for an arbitrary upstream T-space description.

source

Request construction does not require an installed backend:

julia> using PerfectForms

julia> request = perfect_form_request(5);

julia> occursin("RealQuad", request)
true

julia> occursin("ComputeComplex = F", request)
true

Backend selection and execution

PerfectForms.BackendConfig — Type

One absolute exporter path, its SHA256 and the expected upstream commit.

Construct with BackendConfig(path; expected_sha256=nothing, commit=...). The executable is checked when configured and again immediately before launch.

source
PerfectForms.default_backend — Function

Select an installed exporter.

Set PERFECT_FORMS_BACKEND_CONFIG to the absolute path of an installed config.json, or pass config_path explicitly. Otherwise use the last successful Pkg.build("PerfectForms") installation for this package checkout/version, falling back to the checkout's backend/config.json for manual CMake installs. An unset or empty environment variable uses this automatic selection. Loading the Julia package does not download sources or compile C++.

source
PerfectForms.backend_build_info — Function

Read CMake build provenance, checking that it describes the selected executable.

path defaults to the provenance installed beside the executable's bin/ directory. For an uninstalled build, pass its backend-build.json explicitly.

source
PerfectForms.run_exporter — Function

Run an executable with private files, an outer deadline and bounded memory.

Call run_exporter(input_text, config=default_backend(); ...) with a namelist. Return (data, raw, run_directory, process_info) after checking the request token, schema, completion marker and upstream commit. Mathematical validation is the caller's responsibility. Diagnostic files are retained on failure.

The default memory policy is a hard address-space limit on Linux and a sampled resident-memory watchdog on macOS. The resident policy can also be selected on Linux, including for ASan executables whose virtual shadow memory is large.

source
PerfectForms.BackendError — Type
BackendError

Backend failure with a symbolic kind, a human-readable message, and a run_directory containing diagnostics when a request directory was created.
